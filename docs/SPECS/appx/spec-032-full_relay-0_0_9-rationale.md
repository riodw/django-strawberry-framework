# Rationale companion: spec-032 (Full Relay story)

Companion to [`docs/SPECS/spec-032-full_relay-0_0_9.md`][spec-032]. It carries that spec's **deliberative layer** and nothing else: the eight-revision review history that produced the contract, every Decision's justification, every alternative a Decision rejected and why it lost, and the risk / open-question deliberation that settled the card's design questions. The spec carries the contract; this file carries how the contract was arrived at. Neither duplicates the other — the text here **left** the spec.

Read this when checking a finished implementation against the reasoning that produced it, or before re-opening a settled question. Worker 2 never reads it ([`docs/builder/BUILD.md`][build-md] `### Who reads it, and when`).

**How later passes append to this file.** Each Decision below carries a `### Changes this Decision underwent` section. A reconciliation pass that finds the spec stale against `HEAD` — a renamed symbol, a bound a later card removed, a claim the Decision may no longer make — appends a `**Post-ship:**` bullet there, naming the shipped behavior and the card that changed it. Findings belonging to no single Decision go under [Non-Decision deliberation](#non-decision-deliberation). Nothing needs restructuring to take an addition, and the corrections themselves always land in the spec, stated directly and without chronology.

## Decision 3 — Root fields dispatch through the package decode, not Strawberry's native node field

Spec: [Decision 3 — Root fields dispatch through the package decode, not Strawberry's native node field][spec-032-d3].

### Justification (moved from the spec)

- **Native dispatch cannot decode the default payload.** Strawberry's `NodeExtension` resolves `node_type = id.resolve_type(info)` = `info.schema.get_type_by_name(type_name)` (source-verified, `0.316.0`). The `0.0.9` default emits model-label payloads (`library.genre:42`); no schema type carries that name, so the native field fails for every default-strategy id. [`spec-031`][spec-031] shipped `decode_global_id` exactly as "the forward-looking helper `032` dispatches through".
- **The card mandates server-side distrust.** "Decode the GlobalID server-side (never trust the client's claim of which type the ID belongs to)" — `decode_global_id`'s resolve-then-enforce dispatch rejects payload shapes the resolved candidate's recorded strategy does not emit, which the native schema lookup cannot do.
- **The permission contract is already downstream.** `decode_global_id` returns the *type*; the shipped `resolve_node` / `resolve_nodes` defaults run [`get_queryset`][glossary-get_queryset-visibility-hook] on both sync and async branches, so dispatching to them gives the card's "respects `get_queryset`" requirement with zero new permission code.
- **Engine reuse everywhere else.** `GlobalID` parsing, the `Node` interface, the field machinery, and the connection mechanics all stay Strawberry's ([`START.md`][start] "Strawberry is the engine"); only the type-resolution hop is package-owned, because it is the one hop the engine resolves by GraphQL type name.

### Alternatives considered (and rejected)

- **Use Strawberry's `relay.node()` and require the `type` strategy for refetchable types.** Rejected: it would make the `0.0.9` model-anchored default — the headline of [`DONE-031-0.0.9`][kanban] — incompatible with the Relay story shipping in the same release; the two cards were sequenced precisely so the root fields decode the new payload.
- **Patch `GlobalID.resolve_type` to recognize model labels.** Rejected: process-global monkeypatching of engine internals, breaks non-package Strawberry usage in the same process; the per-field resolver is surgical (the same reasoning that rejected the global `resolve_typename` patch in [`spec-031`][spec-031] [Decision 3][spec-031-rationale-d3]).
- **A registry-backed `Schema` subclass overriding type resolution.** Rejected: forces a package-owned `Schema` class onto consumers — a much larger surface commitment than two field factories, and contrary to the `strawberry.Schema(...)` + [`strawberry_config`][glossary-strawberry_config] composition every shipped example uses.

### Changes this Decision underwent

- **Revision 1** established the package-owned dispatch, source-verified against the locked Strawberry `0.316.0` (`NodeExtension.get_node_resolver` resolves the type through `info.schema.get_type_by_name`, which cannot see a `library.genre` model label). No later revision reopened it.
- **Post-ship: both root fields gained a cooperative execution-deadline check** (`resource_policy.py::check_deadline`), landed by the `0.0.14` execution-resource-policy card ([`DONE-047-0.0.14`][kanban], commit `567cc6d0`) alongside the rest of the resource-policy surface. Nothing in this Decision was reopened — the dispatch is unchanged — but the two fields now sit inside a package-wide pre-query seam the spec never described. The **placement** is the part worth recording as deliberate rather than incidental: the single field checks before the decode, because the decode is what makes a visibility-scoped query inevitable, while the batch field checks *after* its empty-list short circuit, so a request asking for nothing is never rejected for a budget it cannot spend. The alternative — one check at the top of each resolver — was rejected on exactly that empty-list case. Stated as contract in the spec's Decision 3 and [Edge cases][spec-032-edge-cases].

## Decision 4 — `DjangoNodeField` / `DjangoNodesField`: a bare interface form and a typed form

Spec: [Decision 4 — `DjangoNodeField` / `DjangoNodesField`: a bare interface form and a typed form][spec-032-d4].

### Justification (moved from the spec)

- The card pins the canonical signatures (`node(id: ID!): Node`, `nodes(ids: [ID!]!): [Node]!` with positional `null`s — the `ID` scalar form per the Argument-spelling bullet above) and the DoD exports both symbols; [`GOAL.md`][goal] independently pins the typed shape as the `1.0.0` consumer surface. One factory with an optional target serves both without a third symbol.
- The typed mismatch **error** (rather than `null`) is graphene-django's `Node.Field(only_type)` posture: a wrong-type id at a typed field is a client bug, and surfacing it costs nothing — the check runs on decoded payload data before any database query, so it cannot leak row existence.
- Batched per-type `resolve_nodes` is the only shape that scales a heterogeneous `nodes(ids:)` list — one query per distinct type rather than one per id.

### Alternatives considered (and rejected)

- **Separate `DjangoNodeField` (typed-only) and a `DjangoRootNodeField` (bare).** Rejected: two names for one concept; the optional-argument form matches `DjangoConnectionField(target)` / `DjangoListField(target)` muscle memory while keeping the bare Relay-spec spelling available.
- **Typed mismatch returns `null`.** Rejected: it silently masks client bugs (an Item id at a `genre:` field is a programming error, not a visibility outcome), and the Relay-spec `null` contract is about *visibility*, which the mismatch check — running pre-query — never touches.
- **`nodes` raises on any missing id.** Rejected: the card pins "missing IDs become `null` entries (preserves positional correspondence)", which is also Strawberry's `required=not is_optional` behavior for the optional-entry annotation.

### Changes this Decision underwent

- **Revision 6 P2** — the typed `DjangoNodesField` had zero tests and its batch malformed-id semantics were unpinned. The Decision gained the rule that a wrong-type id **anywhere** in a typed batch fails the whole field (`[Node]!` non-null nulls `data`), never a per-position `null`, and Slice 2 gained `test_typed_nodes_field_resolves_targets` / `..._mismatch_raises`.
- **Revision 6 P3** — the stated async mechanism could not produce the `nodes` reassembly. The `nodes` semantics bullet gained the per-call `in_async_context()` dispatch and the single gathering coroutine, deliberately the *other* mechanism from `connection.py`'s commit-at-construction split.
- **Revision 6 P3** — [`GOAL.md`][goal]'s typed showcase used the non-optional spelling [Decision 5](#decision-5--null-for-invisible-rows-graphqlerror-for-malformed-ids) declares unsupported. The Decision records the tension and Slice 7's doc list flips both showcase fields to `… | None`.
- **Revision 7 P1** — the `GLOBALID_INVALID` contract was unreachable as originally specced, because Strawberry's `strawberry/types/arguments.py::convert_argument` special-cases a `relay.GlobalID` argument *before* the resolver. The Decision gained the whole **Argument spelling** bullet (`strawberry.ID`, byte-identical SDL) and the canonical signatures; the `relay.GlobalID`-argument form is recorded as a rejected alternative under [Decision 5](#decision-5--null-for-invisible-rows-graphqlerror-for-malformed-ids).
- **Build finding (Slice 2, commit `1f16d963`) — `is_type_of` injection alone cannot route a multi-type model, and the Decision's claim that it could was insufficient as written.** The bare-form bullet said plain unconditional `is_type_of` injection "lets Strawberry resolve each returned model instance to its concrete GraphQL type". For a model carrying **two** registered Relay types the injected closure's `isinstance(obj, (type_cls, model))` answers `True` on both candidates, so graphql-core's candidate iteration order — not the `GlobalID` — picks the `__typename`. The build shipped `relay.py::_stamp_node_type`, which stamps the decode-resolved `DjangoType` on the fetched instance under `types/relay.py::_NODE_TYPE_HINT_ATTR`, and taught `types/relay.py::install_is_type_of`'s closure to honor the stamp **before** the isinstance fallback. Two sub-decisions are recorded here because the spec states only their outcome: the instance is **shallow-copied** before stamping (rejecting the cheaper in-place `setattr`, which would leave a routing hint on an ORM object a consumer reuses in another field or request), and the stamp is **best-effort** on a non-model or `__slots__` object a consumer override may return (rejecting a raise, which would turn a routing optimization into a new failure mode for a shape the pre-032 isinstance path handled fine). Unstamped instances keep the pre-032 behavior exactly.
- **Build finding (Slice 2, commit `3e247237`) — the `resolve_nodes` override return shape is a consumer-facing contract, and the spec pinned neither the contract nor its enforcement.** `_interleave` indexes each per-type result by its **within-group position**, so an override returning an unordered, shrunk, or duplicate-collapsed list yields silently wrong rows or an `IndexError`. The obvious spelling a consumer reaches for — `get_queryset().filter(pk__in=node_ids)` — is exactly that shape. The build added `relay.py::_check_nodes_result`: a structural length check converting the shrunk / duplicate-collapsed case into a named `ConfigurationError`, with a generator / iterator return materialized first so it reaches the check instead of dying on a bare `len()`. A full positional verification was rejected as unaffordable per request; ordering stays a documented obligation rather than a re-validated one, on the reasoning that the cheap check catches the failure a consumer actually writes while the expensive one would charge every correct override for it.

## Decision 5 — Null for invisible rows, GraphQLError for malformed ids

Spec: [Decision 5 — Null for invisible rows, GraphQLError for malformed ids][spec-032-d5].

### Justification (moved from the spec)

- The Relay spec requires `null` (not an exception) for an unresolvable-but-well-formed node lookup, and the card pins it twice; the shipped `resolve_node` default with `required=False` already implements the single-code-path property.
- A malformed id is a *request* error: silently returning `null` for it would make client bugs (truncated ids, double-encoding) indistinguishable from visibility outcomes — the exact debugging trap the loud-`GraphQLError` posture of the `first`+`last` guard and the filter layer's `Invalid filter input` (`extensions={"code": "FILTER_INVALID"}`) already avoids. The `GLOBALID_INVALID` code follows that shipped naming convention.
- Converting at the field boundary (rather than letting [`ConfigurationError`][glossary-configurationerror] bubble raw) keeps internal exception classes and `decode_global_id`'s implementation-flavored messages out of the public wire contract while preserving the diagnostic reason.

### Alternatives considered (and rejected)

- **`null` for everything (malformed included).** Rejected: masks client bugs; loses the strategy-enforcement signal (`031`'s Step-2 rejections exist to be *seen*).
- **Annotation-sensitive `required=True` dispatch** (a non-optional field annotation routes to `resolve_node(..., required=True)` so a missing row raises the model's `DoesNotExist` — Strawberry's native `required=not is_optional` shape). Rejected (Revision 2 P2): it forks the single null code path the no-existence-oracle property depends on, and the spec centers the Relay null contract throughout; a consumer who wants a raising lookup writes a plain field over `get_queryset` themselves. An earlier draft's "non-optional annotation surfaces `DoesNotExist`" promise is deleted — it only held under exactly this rejected dispatch.
- **Raw `ConfigurationError` for malformed ids.** Rejected: leaks internal exception taxonomy into the wire contract; the message text would become an accidental API.
- **Declare the id argument as `relay.GlobalID`** (rather than `strawberry.ID`). Rejected (Revision 7 P1): Strawberry's `strawberry/types/arguments.py::convert_argument` runs `GlobalID.from_id(value)` during argument conversion, *before* the resolver — a malformed base64 / non-`type:id` payload then raises the engine's `GlobalIDValueError` upstream of the package, the wire response carries Strawberry's internal error text with **no** `GLOBALID_INVALID` extensions code (an accidental API), and `decode_global_id`'s `from_id`-`ValueError`-wrapping branch is dead code on that path — so the `GLOBALID_INVALID` contract above would be unreachable for exactly the malformed cases it exists to cover. Declaring `strawberry.ID` and feeding the raw string to `decode_global_id` (which accepts `relay.GlobalID | str`) lets the package own every failure shape uniformly; the SDL is byte-identical (`GlobalID` renders as `ID` under Strawberry's modern `relay_use_legacy_global_id = False` default). The weaker fallback — keep `relay.GlobalID` and split the contract so malformed-shape failures surface Strawberry's argument-conversion error (pinning only that it is an in-band GraphQL error, never a 500) while `GLOBALID_INVALID` covers post-parse decode failures only — was rejected for using two error vocabularies for one client-mistake family.
- **HTTP-level 4xx for malformed ids.** Rejected: GraphQL errors travel in-band; the transport stays 200 per the GraphQL-over-HTTP convention the rest of the package follows.

### Changes this Decision underwent

- **Revision 2 P2** — the root-field nullability contract contradicted itself. Resolved to nullable-by-contract: `resolve_node` / `resolve_nodes` are dispatched `required=False` unconditionally and the optional annotation spelling is the supported shape. **The earlier draft's "a non-optional annotation surfaces the model's `DoesNotExist`" promise was deleted rather than moved** — it held only under the annotation-sensitive dispatch this Decision rejects, so it was false as written. The rejected dispatch is recorded above.
- **Revision 6 P2** — batch semantics for a malformed or wrong-type id were unspecified. The Decision gained the whole-field failure rule and the reservation of positional `null` for well-formed-but-invisible/missing ids.
- **Revision 7 P1** — the `GLOBALID_INVALID` reachability clause was added (the contract exists only because the argument is `strawberry.ID`), and the `relay.GlobalID`-argument form plus its split-contract fallback were recorded as rejected alternatives.
- **Revision 7 P2** — a wide catch-convert would have mislabeled [`SyncMisuseError`][glossary-syncmisuseerror] (a [`ConfigurationError`][glossary-configurationerror] subclass) as a client id error. The catch scope was pinned to the `decode_global_id` call only, and `test_node_sync_async_get_queryset_raises_sync_misuse` gained a discriminating assertion.
- **Revision 7 P2** — a well-formed id with an uncoercible pk literal leaked a Django `ValueError`. The uncoercible-pk family was added as an *existence* outcome (`model._meta.pk.to_python` pre-coercion under `try` / `except (ValueError, ValidationError)` → `null` / positional `null` hole, no query issued).
- **Build finding (Slice 2, commit `3e247237`) — coercing against `model._meta.pk` unconditionally was the wrong field, so the pre-coercion was generalized to the id slot.** The dispatch filters on the concrete field behind `resolve_id_attr()`, which is `model._meta.pk` only for the default; a consumer `id: relay.NodeID[...]` annotation makes the id slot a non-pk column, and that annotation is also the documented composite-pk escape hatch, where `_meta.pk` is a `CompositePrimaryKey` with no single-column `to_python` at all. Coercing the wrong field mis-types the value — `"007"` against an integer pk becomes `7`, which then filters `code=7` rather than `code="007"` — or spuriously rejects a literal an existing row carries. That reasoning **stays in the spec** rather than moving here: it is implementation-relevant rationale under the `worker-1.md` carve-out, because a builder who reads only "pre-coerce to the pk type" writes the bug back. Two later refinements are post-ship rather than this card's: `c1f20f49` moved the mechanics into the shared `utils/querysets.py::coerce_field_value_or_none` primitive and added `run_validators` after `to_python`, so an in-range-looking but out-of-range literal is rejected before a `pk__in` can raise a backend `OverflowError`; `f92c1944` factored the slot lookup into `relay.py::_node_id_slot`, the single statement the READ coercer and the WRITE pk-mapper share.
- **Post-ship: the root fields reject a consumer override's awaitable in a sync context themselves.** The Decision said only that `SyncMisuseError` is inherited from the `resolve_node` / `resolve_nodes` defaults, unchanged — true for the framework default's async `get_queryset` branch, and silent about the *other* way an awaitable reaches a sync field: a consumer `resolve_node(s)` **override** that is `async def`. Commit `dc00f4a6` wrapped both dispatch results in `utils/querysets.py::reject_async_in_sync_context` with a root-field recourse string, so the orphaned coroutine is closed and named rather than treated as a truthy result. **This is a post-ship change, not this card's own build** — the pre-dispatch verification filed it under the card's own surface, and the commit trace says otherwise; the correction is recorded so a later reader does not attribute it to `0.0.9`. Both sources sit outside the decode catch-convert boundary, so this Decision's narrow-catch rule is what keeps either from being mislabeled `GLOBALID_INVALID` — the rule held under a change it was not written for, which is the argument for having scoped it narrowly in the first place.

## Decision 6 — Relation-as-Connection synthesis at finalization Phase 2.5

Spec: [Decision 6 — Relation-as-Connection synthesis at finalization Phase 2.5][spec-032-d6].

### Justification (moved from the spec)

- Phase 2.5 is the only correct home: relation targets are settled (Phase 1), generated relation resolvers exist (Phase 2), and `strawberry.type` has not yet frozen the annotation set (Phase 3) — the same reasoning that placed interface application and sidecar binding there.
- The implicit `"both"` default is the card's pre-pinned direction ("Implicit upgrade (default): every `DjangoType` whose `Meta.interfaces` includes `relay.Node` automatically exposes its reverse-FK and M2M relations as Connections **in addition to** the existing `list[T]` shape", default `"both"` for Relay types) — preserved as a Decision, not re-litigated.
- Requiring a Relay-Node-shaped **target** mirrors the shipped `DjangoConnectionField` fifth guard: a connection's `node` field is typed by the target, and a connection of non-Node types has no Relay identity. Degrading silently to list-only under the *default* (while failing loud on an *explicit* request) keeps existing valid schemas building — the library's `GenreType.books` over the non-Node `BookType` must not start erroring because this card landed.
- Seeding from the relation manager (not the default manager) keeps Django's prefetch caches reachable — the seam [`DONE-033-0.0.9`][kanban]'s window-pagination planning cooperates with.

### Alternatives considered (and rejected)

- **Synthesize at class-creation time (`__init_subclass__`).** Rejected: relation targets may be undeclared at that point ([Definition-order independence][glossary-definition-order-independence]); the target-is-Node-shaped gate needs settled definitions.
- **Connections only on explicit `Meta.relation_shapes` opt-in (no implicit default).** Rejected: the card pre-pins the implicit upgrade as the default; per-relation opt-in is the `"list"` narrowing, not the baseline.
- **Allow connections over non-Node targets (plain edges, no `GlobalID`).** Rejected: contradicts the shipped `DjangoConnectionField` guard and produces connections whose nodes are not refetchable — the broken half of the Relay contract this card exists to complete.
- **A `<field>s_connection`-free naming scheme (replace the list field wholesale).** Rejected: silently removing the shipped `list[T]` shape is a breaking schema change for every existing Relay-shaped consumer; the sibling-field convention (`itemsConnection` alongside `items`) is the card's stated naming and is additive.

### Changes this Decision underwent

- **Revision 1** placed the synthesis at finalization Phase 2.5 and fixed the `"both"` default.
- **Revision 3 P3** — the `<field>_connection` collision guard checked Python attribute names only, so a consumer-authored `booksConnection` would collide in SDL with a generated `books_connection` under default camel-casing. The guard now compares both spellings; a non-default `name_converter` / `auto_camel_case=False` config is unknowable at finalization and falls through to Strawberry's own duplicate-field error, pinned as a documented constraint.
- **Post-ship: the default shape flipped from `"both"` to `"connection"`** (`types/base.py::DEFAULT_RELATION_SHAPE`, landed by the `0.0.14` security card [`DONE-047-0.0.14`][kanban], commit `567cc6d0`, attributed in-source to that card's Decision 5). This is the single largest change any part of this spec has undergone, and it inverts a default this Decision fixed in Revision 1. The reason is a security one, not a taste one: a raw many-side list has no cursor and therefore no page of its own, so emitting one **beside** the bounded connection hands a client a way around the connection's cap by selecting the sibling. Connection-only became the shape an eligible relation receives; the raw list became an explicit `Meta.relation_shapes = {...: "both"}` opt-in, and the list that opt-in produces is row-bounded (`resource_policy.py::bounded_rows`) rather than unbounded. Three things this record has to carry, because the spec now states only the outcome:
  - **The justification bullet that fixed `"both"` is superseded.** "The implicit `"both"` default is the card's pre-pinned direction … preserved as a Decision, not re-litigated" was a good reason at the time and remains the reason `0.0.9` shipped that way — but the card's pre-pinning is no longer what the package does, and a reader who finds only that bullet would conclude the current default is a drift rather than a decision.
  - **The additive / non-breaking argument the Decision rested on is falsified by shipped code.** The claim was that `"both"` never removes anything, so no existing schema changes shape without a consumer edit. The default now suppresses the list sibling, so an eligible relation on a Relay-Node-shaped type **does** change shape across `0.0.14` without a consumer edit. That is a deliberate breaking change made by a security card, accepted as such; it is recorded here rather than hedged in the spec, which states today's contract directly.
  - **A rejected alternative was later adopted, for a different reason.** "A `<field>s_connection`-free naming scheme (replace the list field wholesale)" lost this Decision's Revision-1 argument on the grounds that silently removing the shipped `list[T]` shape is a breaking schema change for every existing Relay-shaped consumer. The package subsequently did remove the list by default — but note precisely what was and was not adopted: the *naming* half of that alternative was **not** taken (the field is still `<field>Connection`, never a renamed `<field>s`), and the removal was adopted on a cap-bypass argument the Revision-1 deliberation never weighed, not because the breaking-change objection was found wrong. The objection was correct and was overridden. Left standing unqualified, the rejection reads as a live prohibition on exactly the behavior the package ships.
- **Build finding (Slice 3, commit `d418e649`) — the synthesis step must survive being run twice, and the spec never said so.** `finalize_django_types` documents a re-call as the recovery path after a partial Phase-2/2.5/3 failure, which re-enters this Decision's step over classes it already mutated. Without a marker on the attached field, the rerun reads its own prior attachment as a name collision and raises `ConfigurationError` on a schema that is merely recovering. The build stamped every synthesized field object with `_SYNTHESIZED_RELATION_CONNECTION_MARKER` and skipped on it. Recorded as contract in the spec's [Edge cases][spec-032-edge-cases].
- **Post-ship: the re-entrancy path grew two obligations the bare marker skip did not have** (commit `c3767495`, `fix(types): harden finalization lifecycle`, with a naming pass in `77d923ab`). First, a plain skip was **not enough for a `"connection"` shape**: a rerun's Phase 2 re-attaches the generated list resolver, so skipping on the marker leaves a re-attached, now-unannotated relation resolver that breaks Phase 3 — the list form has to be removed **again**. Second, teardown: `registry.clear()` previously left the synthesized field and the suppressed annotations on the class, so a fresh-registry test cycle inherited the prior cycle's shape. The fix registers a per-attachment inverse that is **identity-safe** — it recognizes only the two framework-owned objects it created (the `StrawberryField`, and the resolver function `strawberry.type` replaces it with) and restores a suppressed value only into a slot still vacant. The alternative, an unconditional restore, was rejected because it would clobber a consumer replacement made after finalization; the narrower contract is deliberate and is why the teardown is class hygiene for the test lifecycle rather than a general unfinalizer.
- **Post-ship: the resolver gained the arguments the [`DONE-033-0.0.9`][kanban] walker needs, and one it needed all along.** The spec described the resolver only as relation-manager-seeded. Three arguments now flow into it. `instance_accessor(field)` (commit `1f16d963`, the card's own build) is the card-era fix for a reverse relation declared without `related_name`, where Django's `ForeignObjectRel.name` is the related *query* name and the instance attribute is `get_accessor_name()` — `getattr(root, field.name)` raised `AttributeError` there, invisible to CI because every fakeshop fixture sets `related_name`. The **relation field name** and the **declaring type** are `033`'s (commit `75035bdc`): the field name is the key the walker builds its window `to_attr` from, and the declaring type is the `parent_type` the walker keyed the planned connection under, passed as the iterated `type_cls` rather than `registry.get(model)` so a divergent secondary type's strictness key is not aliased onto the primary's. The same commit added `_record_relation_connection`, the walker-readable `generated -> relation field name` slot on the definition; `c3767495` made it re-recorded on the re-entrant path, because a failed pass can drop the slot while leaving the field attached.
- **Post-ship: two spec-named Slice-3 tests were renamed, and one became three.** `test_default_both_synthesizes_connection_sibling` is now `test_default_connection_only_drops_the_reverse_fk_list_sibling` + `test_explicit_both_restores_the_reverse_fk_list_sibling` + `test_default_connection_only_covers_both_m2m_directions` (`tests/test_relay_connection.py`) — the split is the direct consequence of the default flip: what was one additive assertion became a presence **and** an absence, plus a separate test for the opt-in that puts the list back. `test_relation_shapes_on_consumer_authored_relation_raises` is now `test_relation_shapes_on_consumer_annotated_relation_raises` + `test_relation_shapes_on_consumer_assigned_relation_raises` (`tests/types/test_base.py`), one per corner of the override contract. Each body was read against the sentence it is cited for, not matched by name.

## Decision 7 — `Meta.relation_shapes` is a net-new `ALLOWED_META_KEYS` key, stored on the definition

Spec: [Decision 7 — `Meta.relation_shapes` is a net-new `ALLOWED_META_KEYS` key, stored on the definition][spec-032-d7].

### Justification (moved from the spec)

identical to the four precedents — the key's feature ships in this card, the finalizer reads definitions (not re-parsed `Meta`), and gating to Relay-Node types keeps the eligibility rule single-sited with `Meta.connection` / `Meta.globalid_strategy`.


### Alternatives considered (and rejected)

- **A `DEFERRED_META_KEYS` promotion.** Rejected: never reserved; ships functional now.
- **A boolean `Meta.relation_connections = True`.** Rejected: cannot express the per-relation `"list"` / `"connection"` / `"both"` narrowing the card pre-pins.
- **Defer all validation to finalization.** Rejected: name-level typos are detectable at type creation, and the package's posture is fail-at-the-earliest-phase-that-can-know ([`Meta.optimizer_hints`][glossary-metaoptimizer_hints] precedent); only the target-shape check genuinely needs finalization.

### Changes this Decision underwent

## Decision 9 — Cursor mechanics stay delegated to Strawberry; this card pins the conformance contract

Spec: [Decision 9 — Cursor mechanics stay delegated to Strawberry; this card pins the conformance contract][spec-032-d9].

### Justification (moved from the spec)

[`spec-030`][spec-030] Decision 9 already delegated cursor mechanics, on the [rationale its companion records][spec-030-rationale-d3] that re-implementing cursor math duplicates correct engine behavior; re-implementing it here to match an illustrative byte format would churn the shipped wire contract for zero consumer value. The conformance suite is the card's actual deliverable ("Cursor pagination math passes the package's hand-authored Relay-spec conformance suite").


### Alternatives considered (and rejected)

**Re-implement cursors as literal `b64("offset:N")`.** Rejected: breaks every cursor minted since [`DONE-030-0.0.9`][kanban], duplicates `ListConnection`, and buys nothing — both formats are equally opaque to a compliant client.

### Changes this Decision underwent

- **Revision 2 P1** — the stale-`after` "falls through to the next existing row" claim was **false** for Strawberry's offset cursors: `strawberry/relay/utils.py::SliceMetadata.from_arguments` decodes `after` to a numeric offset (`start = int(after) + 1`), so the cursor encodes a position, not a row identity. Every site asserting positional stability was reduced to the no-error property alone, and `test_stale_after_cursor_falls_through` was renamed `test_stale_after_cursor_no_error`.
- **Revision 6 P3** — `test_has_next_page_correct_when_unrequested` asserted an unobservable property (a GraphQL response omits unrequested fields). The observable inverse — `hasNextPage` correct on a `pageInfo`-only query, where Strawberry's `should_resolve_list_connection_edges` takes a distinct path — replaced it, and the test was renamed `test_has_next_page_correct_when_edges_unrequested`.
- **Build finding (Slice 4)** — the `first`+`last` guard was discovered to be schema-bypassed for bare connection types: Strawberry's generic specialization copied `DjangoConnection[T]` into a plain specialized class whose `resolve_connection` is `ListConnection`'s, dropping the package override. The root-cause fix — `_connection_type_for` always returning a generated concrete `<TypeName>Connection` subclass — is stated as contract in the spec, because a builder who does not know the mechanism reintroduces the bare alias.
- **Post-ship: `Meta.cursor_field` shipped, and this Decision is the reason that cost nothing here.** The keyset value-encoded cursors this Decision put out of scope — `Meta.cursor_field` in [`types/base.py`][base] `ALLOWED_META_KEYS`, two-stage validated by `_validate_cursor_field` plus finalization column validation, with the codec and seek logic in the net-new [`keyset.py`][keyset] — landed at commit `51421e54` (the BACKLOG item 39 sub-feature 3 card). **Nothing in this Decision was reopened and nothing in the offset path changed**, which is the record worth keeping: the Decision's whole content is *delegate, and pin the conformance contract instead of the bytes*, and a delegation is exactly what makes a second cursor vocabulary additive rather than a rewrite. `DjangoConnection` gained a keyset dispatch beside the offset one; a type that declares no `cursor_field` still resolves through Strawberry's `arrayconnection:N` payload byte-for-byte. **The three-case grading matters here and is easy to get backwards.** The scope sentences (*this card* ships no cursor code; the conformance suite must not assert keyset properties against the offset path) are **case (c)** — statements about this card, still true, and rewriting them into "the package has no keyset cursors" would be a new false claim. Only the **placement** sentences were case (a): an unqualified "stable column-keyed cursors are BACKLOG item 39 sub-feature 3" reads as present tense about the package and is false, so [Edge cases][spec-032-edge-cases], [Non-goals][spec-032-non-goals], [Out of scope][spec-032-out-of-scope] and this Decision's closing line now name the shipped surface while keeping the card-scope claim intact. One consequence is worth naming because a later reader will meet it: the "Cursor byte-format wording" item below records the offset payload as the shipped format, and that item is **not** falsified — a `cursor_field` connection uses a different prefix by design, so the two vocabularies can never be confused for one another silently. The item's fallback (a `CURSOR_PREFIX` override for byte-exactness) was neither taken nor needed.
- **Post-ship: a connection page has a second bound the spec named nowhere.** [`resource_policy.py::ResourcePolicy.max_page_size`][resource-policy] (default `100`) is a **ceiling** over a connection's effective `relay_max_results`, resolved once at the connection's entry seam before any window or slicing path reads the value, so plan-time and resolve-time windows agree by construction. The spec had said `relay_max_results` was *the* knob and that a consumer raises it via `strawberry_config(...)`; the second half is what actually rots — a raise above the policy has no effect. The correction went to the [Key glossary references][spec-032-key-glossary] `strawberry_config` bullet, this Decision's lead-in, and the [Edge cases][spec-032-edge-cases] entry, which is retitled so the ceiling is in the entry's own name rather than in its body. Recorded as deliberate: `max_page_size` and `max_node_ids` are independent fields precisely so raising a page size never raises a refetch batch, which is the same reasoning the [Risks](#risks-and-open-questions) item-7 note gives from the batch side.

Preferred answer ([Decision 9](#decision-9--cursor-mechanics-stay-delegated-to-strawberry-this-card-pins-the-conformance-contract)): keep the shipped format — both are opaque offset cursors and the card's wording is conceptual; changing bytes now would break every cursor minted since [`DONE-030-0.0.9`][kanban]. Fallback: a `CURSOR_PREFIX` override on [`DjangoConnection`][glossary-djangoconnection] if byte-exactness is ever required.
- **Nested-connection optimization belongs to [`DONE-033-0.0.9`][kanban].** The relation-as-Connection upgrade ships functionally complete, with behavior-only live assertions; connection-aware planning, the strictness-mode interaction, and the SQL-shape coverage are `033`'s deliverables ([Decision 12](#decision-12--sequencing-against-the-connection-aware-optimizer-and-the-library-first-activation); [Non-goals][spec-032-non-goals]). Both cards ship in the same `0.0.9` cut, so no released version carries the gap.
- **`BookType` Relay-promotion blast radius.** Promoting `BookType` flips its `id` to `GlobalID!` and churns existing library assertions, and adds a `BookType.get_queryset` (the hidden-row test's eligible type). Because `BookType` is the [`Meta.primary`][glossary-metaprimary] relation target for `library.Book`, that filter now runs for every relation resolving to a book (`Shelf.books`, `Genre.books`, `Loan.book`). Preferred answer: bounded, mechanical churn (the [`spec-031`][spec-031] Slice-4 precedent) — the `circulation_status="repair"` predicate matches no existing inline-created test row, and the live `booksConnection` behavior test creates only visible books, so no existing assertion changes shape — worth it for a real live relation-connection proof and a live hidden-row proof. Fallback: keep `BookType` non-Relay and prove relation-as-Connection **and** the hidden-row `null` only in package tests, deferring both live proofs to the products activation (`0.1.5`).
- **`nodes(ids:)` is uncapped in `0.0.9`.** Unlike connection pages (capped by `relay_max_results`), a `nodes(ids: [...])` batch is unbounded — a 10,000-id request issues a 10,000-key decode loop and `pk__in` query. Preferred answer ([Edge cases and constraints][spec-032-edge-cases], Revision 7 P3): no cap, matching both upstreams (Strawberry's native batch resolver and graphene-django cap neither), with request-size limiting left to the consumer's transport / rate-limit layer. Fallback: an opt-in batch cap reusing the `relay_max_results` value (rejecting an over-cap `ids` list with the same error vocabulary the connection cap uses) — deferred to a BACKLOG item rather than scoped here, since no shipped consumer needs it and a silent cap would surprise the Relay-spec `nodes` contract.
- **Interface-only schema reachability.** A consumer schema whose only root field is the bare `node` cannot reach concrete types for schema registration (engine behavior). Preferred answer: document the `strawberry.Schema(types=[...])` recourse in the root-field docstring and [`docs/GLOSSARY.md`][glossary]; every shipped example already reaches its types through other fields. Fallback: a package helper that feeds all registered Relay-Node types into `types=` — deferred until a consumer actually hits the edge (tested-usage discipline).
- **Suppressing the list field under `"connection"` interacts with sidecar resolvers.** Removing a generated list relation after consumers may have referenced it in hand-written resolver annotations is consumer-visible. Preferred answer: `"connection"` is an explicit opt-in narrowing; the default `"both"` never removes anything, so no existing schema changes shape without a consumer edit. Fallback: none needed — the failure mode requires the consumer to both opt in and keep stale references, which fails loud at schema build.

## Non-Decision deliberation

Findings and provenance that belong to no single Decision.

- **Revision 3 (P2) — normative sections cited a mutable review document.** The Revision-2 edits cited "the review pass P1/P2" from Decisions 5 / 9 / 10, the checklists, the Test plan, and the DoD. That review document is a reusable target each subsequent pass overwrites, so the citations stopped pointing at the text they described the moment the second review landed. Every normative citation was re-pointed at the revision-history entry — the stable, self-contained record — and the `[feedback]` link definition was removed. **This move retires that solution in turn:** the revision history is no longer in the spec, so the 32 surviving `Revision N PN` citations were removed rather than re-pointed, and the contract sentences now state their contracts without provenance. The lesson survives the solution: **a normative sentence must not cite a document that can be overwritten, and a revision log inside the spec is only the second-least-mutable target, not a durable one.**
- **Revision 4 — test-placement compliance against the live-first coverage rule.** The [Test plan][spec-032-test-plan] intro was rewritten to state the [`test_query/README.md`][fakeshop-test-query-readme] rule operatively and to pin, per family, **why** each package-only test is package-only (type-creation / finalization errors cannot appear in the example schema; registry / ledger lifecycle; export imports; [`SyncMisuseError`][glossary-syncmisuseerror] needs a deliberately misconfigured type; async contexts are unreachable through the sync `django.test.Client` WSGI path; `relay_max_results` needs a non-default `StrawberryConfig`; narrowed / reverse-FK relation-connection variants need cardinality fixtures the fakeshop graph lacks). The Slice-4 conformance matrix's **primary copies moved live** against the already-shipped `allLibraryGenresConnection`, and Slice 6 expanded into the mandated live coverage home.
- **Revision 5 — [`AGENTS.md`][agents] compliance.** Verified clean: no raw `path:NN` line references, no pragma / shortcut sequencing, all 10 canonical link-definition group headers present with alphabetical defs, the sub-feature-3 (`Meta.cursor_field`) citations matching [`BACKLOG.md`][backlog] item 39, and the relation-as-Connection upgrade distinct from that item's row-count-threshold variant. Two gaps fixed: the Slice-6 test plan gained the library inline-`Model.objects.create` fixture rule (and the note that the `seed_data(N)` / `create_users(N)` first-line convention is catalog/auth-only), and the Implementation plan gained the `TODO(spec-032 Slice N)` staged-anchor discipline.
- **Revision 7 (P3) — the strategy system is finalize-frozen.** The per-query-overhead worry was defused by verifying the setting is read once per type at finalization and stamped on `effective_globalid_strategy`. The one observable consequence is pinned in the spec's [Test plan][spec-032-test-plan]: an `@override_settings` applied after finalize is inert, so strategy-varying tests must clear the registry and reload. The corollary — [`testing.relay.global_id_for`](#decision-10--public-testingrelaypy-helpers-and-the-export-gate) reads the stamped strategy and is therefore consistent-by-construction with live emission — is a feature, not an accident.
- **Revision 7 (Q4) — test-setup confirmations, no rewrite.** The per-app introspection suite [`test_schema.py`][fakeshop-library-tests] carries no book-id literals, so the `BookType` promotion does not touch it; and the staff-bypass `force_login` infrastructure already existed for the hidden-row test's staff half. Both were recorded in the Slice-6 checklist as checked facts; only the `(Revision 7 Q4)` provenance tag moved here.
- **Foreign-citation census for this move.** A rationale move breaks citations in *other* specs, and no gate sees it because the link still resolves. One site was found: [`docs/SPECS/spec-033-connection_optimizer-0_0_9.md`][spec-033] cites `Revision 6 P2 established that nothing implements strictness for connections` — a citation into the inline revision history this file now owns. No `spec-032-full_relay-0_0_9.md#<anchor>` deep link exists anywhere in the tree, and plain `spec-032 Decision N` citations survive the move untouched because the Decisions themselves stayed in the spec. The repair of the `spec-033` site belongs to the `032` cycle's Slice 3, which owns sibling-spec edits; the standing lesson is that **only history and deliberation citations break in a rationale move — contract citations survive by construction.**
- **Foreign-citation census, closed.** Slice 3 re-ran the census as an **anchor** measurement rather than a distance one: every occurrence of the shortest distinctive token `spec-032` across `docs/`, `django_strawberry_framework/`, `tests/`, `examples/` and `scripts/` — **369 occurrences in 54 files** — was classified rather than only the hits a citation-shaped phrase happened to match. **102 are contract citations** (`Decision N` / `Decisions N/M` / `Goal N` / `Edge cases` / `DoD` / `Slice N` / `Test plan`), which survive the move untouched; **12 are chronology citations** (`Revision N`, `P1`/`P2`/`P3`), of which only **four occurrences at three sites** live outside this cycle's own scratchpads and this file's revision history — the `spec-033` site above (re-pointed at [Decision 12](#decision-12--sequencing-against-the-connection-aware-optimizer-and-the-library-first-activation), whose text was re-verified against the claim rather than merely re-linked) and two `tests/test_relay_node_field.py` comments, re-cited as `spec-032 Decision 4` and `spec-032 Decision 5` after confirming both contracts stayed in the spec; **13 are pre-archive `docs/spec-032-…` path spellings**, the third class; and **242 are bare identity mentions** carrying no citation grammar at all. Two method notes worth keeping. The classifier's own fixtures caught it treating `Decisions 6/7` — the plural, slash-joined spelling — as a non-citation, which had mis-filed a live `types/finalizer.py` reference: **a citation grammar has more spellings than the one the census author happens to write first**, the same failure one order of magnitude smaller than the `Revision N PN` miss recorded above. And the ratio is the durable finding: **a rationale move puts roughly 1% of a spec's inbound references at risk**, which is why an eyeball pass over a 369-occurrence population is not a census and why the classification, not the count, is the deliverable.
- **The pre-archive path spelling is a THIRD rot class, and no gate sees it either.** A spec archived to `docs/SPECS/` keeps working reference-style links — the definitions are relative and were re-pointed by the `NEXT.md` Step 8 sweep — while its **prose** goes on naming `docs/spec-<NNN>-…`. Nothing resolves prose, so nothing fails. In this spec the population was **six sites / seven occurrences** ([Decision 1](#decision-1--spec-filename-and-canonical-naming)'s "lives at" sentence, the [Slice checklist][spec-032-slice-checklist] Slice-7 KANBAN sub-bullet, the matching `## Doc updates` bullet, [DoD][spec-032-dod] item 1 three times — prose path, `-terms.csv` companion, and the `check_spec_glossary.py` invocation — and DoD item 11), where the routed list named five sites and counted DoD item 1 as two. Three more sit in `.py` module docstrings (`tests/test_relay_node_field.py`, `tests/test_relay_connection.py`, `tests/testing/test_relay.py`); the correct `docs/SPECS/` spelling already outnumbers the stale one 26 to 12 across the `.py` trees, so this is rot rather than house convention — measured before editing, per the standing rule that a suspected convention violation is counted tree-wide first. The nine `.py` occurrences naming *other* archived specs are the same rot with no owner here and are routed to the final gate.
