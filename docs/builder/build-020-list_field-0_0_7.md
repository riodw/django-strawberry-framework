## Dispatch-routing deviation, recorded once for both rounds

`worker-0.md` `## Per-slice dispatch` step 4 routes a Worker 3 `revision-needed` to **Worker 2** for the apply-changes pass. On R1 that is impossible and the deviation is deliberate: R1's entire diff is the spec and its rationale companion, and `docs/builder/BUILD.md` `## Spec reconciliation` makes those two files **custodian-only** — "Only Worker 1 may mutate `docs/spec-<NNN>-<topic>-<0_0_X>.md`", and Workers 0, 2, and 3 may only surface issues under `### Notes for Worker 1 (spec reconciliation)`. Dispatching Worker 2 at a spec finding would require Worker 2 to break that rule to do the work. So on R1, and on R1 only, a `revision-needed` routes back to **Worker 1** as the apply-changes pass, and Worker 3 re-reviews afterward. Worker 1 is never its own final auditor: a fresh Worker 1 subagent with no memory of the authoring pass performs final verification, and Worker 3's re-review sits between them. R2 has a genuine builder role (a `README.md` edit and a DB-backed glossary regenerate) and follows the standard routing unchanged.

The maintainer authorized this shape for this cycle: "if it's just the spec file that needs to change then worker-1 alone can do that."

## Integration pass and final gate run in one Worker 1 spawn

`docs/builder/BUILD.md` keeps the cross-slice integration pass and the final test-run gate as two artifacts, and `worker-0.md` `## Integration and final gate dispatch` step 3 already forbids stopping between them. On a two-round, documentation-only cycle with no source diff, the integration pass's cross-round DRY scan is small enough that splitting it across two spawns buys nothing: the same fresh Worker 1 writes `docs/builder/bld-020-integration.md` first, closes it, and only then opens `docs/builder/bld-020-final.md`. Recorded here because a reader counting spawns against the process would otherwise read a skipped step.

## Rules in force for every round

- **One round at a time.** R1 completes its full plan / build / review / final-verification cycle before R2 is dispatched.
- **DRY first.** Worker 1 plans for it, Worker 3 enforces it, and Worker 3's existence challenge — whether an abstraction should exist at all — is in scope.
- **Only Worker 1 mutates the spec** (`docs/builder/BUILD.md` `## Spec reconciliation`). Workers 0, 2, and 3 surface spec issues under `### Notes for Worker 1 (spec reconciliation)`.
- **The spec never narrates its own history.** A corrected decision is rewritten to state the current contract directly — no amendment block, no "as of" hedge. What changed and why lives in the rationale file.
- **Workers never run `pytest` with `--cov*` flags.** `--no-cov` is the only permitted coverage-shaped flag.
- **Workers never commit and never branch.**
