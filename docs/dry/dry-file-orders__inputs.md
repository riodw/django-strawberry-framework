### Mandatory 5-axis duplication probing matrix

1. **Cross-flavor policy mirroring:**
   `orders/inputs.py` mirrors `filters/inputs.py` in module structure and namespace lifecycle, but all namespace materialization, collision checking, clear lifecycle, and emission scaffolding are single-sited in [`make_set_input_namespace`][utils-inputs] and [`emit_set_input_field_triples`][utils-inputs] in `django_strawberry_framework/utils/inputs.py`. Normalization traversal is single-sited in [`iter_active_fields`][utils-input-values] in `django_strawberry_framework/utils/input_values.py`. `orders/inputs.py` supplies the order-specific leaf semantics ([`Ordering`][orders-inputs] enum, `Ordering | None` annotations, and `F(value).asc(...)`/`F(value).desc(...)` `OrderBy` expressions).

2. **Sync and async twins:**
   Zero duplication. AST building, input type registration, and normalization traversal are synchronous operations executed during query execution and schema compilation.

3. **Derived rather than repeated knowledge:**
   Field specs derive camelCase names and Python attribute names from the `OrderSet` definition fields using [`emit_set_input_field_triples`][utils-inputs]. [`Ordering.is_ascending`][orders-inputs] derives ASC/DESC classification directly from member prefix (`self.name.startswith("ASC")`) rather than a hardcoded lookup table. [`_get_concrete_field_names_for_order`][orders-inputs] inspects `model._meta.get_fields()` dynamically.

4. **Inverse and round-trip pairs:**
   [`materialize_input_class`][orders-inputs] writes to module globals and ledger, while [`clear_order_input_namespace`][orders-inputs] cleanly resets the ledger, `_field_specs`, and factory caches. [`_build_input_fields`][orders-inputs] and [`normalize_input_value`][orders-inputs] form an encoder-decoder pair over `_field_specs`.
