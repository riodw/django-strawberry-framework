# Review: `django_strawberry_framework/connection.py`

Status: verified

## Understanding

`django_strawberry_framework/connection.py` implements the Relay Connection pagination subsystem for `django-strawberry-framework`. It bridges Strawberry GraphQL's Relay connection specification with Django ORM QuerySets, windowed prefetching optimizations, keyset cursor pagination, and DRF-style filter/order sidecars.

It owns:
1. `DjangoConnection` base class & dynamic concrete connection type generation:
   - Inherits from `strawberry.relay.ListConnection[NodeType]`.
   - `resolve_connection` enforces pagination bounds (`resolve_relay_max_results`), guards against supplying both `first` and `last` (`_guard_first_and_last`), enforces execution deadlines (`check_deadline`), primes AST selection fields (`prime_selected_fields`), and delegates to windowed row consumption or fallback slicing.
   - `_connection_type_for(target_type)` creates and caches concrete `<TypeName>Connection` subclasses named after `target_type.__django_strawberry_definition__.graphql_type_name`.
   - Opt-in `Meta.connection = {"total_count": True}` dynamically creates a subclass with a `total_count` field (`totalCount` in GraphQL SDL) and `_resolves_total_count = True`.
   - `clear_connection_type_cache()` clears the internal cache and is registered with `registry.py` subsystem clearing.
2. Window prefetch fast-path consumption (`_WindowedConnectionRows`, `_resolve_from_window`, `_consume_window`):
   - Fast-path consumption of window-prefetched rows generated by the optimizer planner (`optimizer/nested_planner.py`), avoiding N+1 queries for nested connection relationships.
   - Decodes window annotations (`_dst_row_number`, `_dst_total_count`, `_dst_keyset_seek_count`), probes sentinels, and handles marker rows for ambiguous empty shapes (`first: 0`, overshot `after:`).
   - Defensive drift detection: if required window annotations or sentinels are missing when `totalCount` or `hasNextPage` are requested, gracefully falls back via `nodes.fallback()`.
3. Keyset cursor pagination (`_resolve_keyset_connection`):
   - Active when the target node type declares `Meta.cursor_field`.
   - Evaluates ordering paths via `_keyset_order_ref` and `_resolve_order_path_field` ensuring ordering targets concrete, non-nullable, database-level scalar columns or forward relations.
   - Translates `before` and `after` value cursors into SQL `WHERE` clauses using `KeysetSeek` and authenticated base64 HMAC cursors (`decode_keyset_cursor`, `encode_keyset_cursor`).
   - Slices `page_size + 1` to probe `hasNextPage` without executing count queries when only edges and page flags are selected.
4. Sync & async query pipeline execution (`_pipeline_sync`, `_pipeline_async`, `_finalize_queryset`):
   - Normalizes sources via `normalize_query_source` (converting Managers to QuerySets).
   - Guards against pre-sliced QuerySets (`_guard_source_not_pre_sliced`) and non-queryset iterables when `filter:` or `orderBy:` are supplied (`_guard_sidecar_input_against_non_queryset`).
   - Enforces execution safety: rejects awaitable sources on sync paths (`reject_awaitable_sync_source`) and residual unawaited coroutines on async paths (`reject_residual_async_source`).
   - Applies type visibility hooks (`apply_type_visibility_sync`/`apply_type_visibility_async`), filterset inputs (`filterset_class.apply_*`), and orderset inputs (`orderset_class.apply_*`).
   - `_finalize_queryset` enforces deterministic ordering (appending primary key tie-breaker via `deterministic_order` unless terminal order column is already unique) and applies connection optimization hints.
5. Field factory & resolver synthesis (`DjangoConnectionField`, `_build_connection_resolver`, `_build_relation_connection_resolver`):
   - `DjangoConnectionField` validates target type (`_validate_relay_djangotype_target`) ensuring `relay.Node` compatibility and builds a Relay connection field.
   - `_synthesized_signature` generates dynamic parameter signatures injecting `filter` and `order_by` keyword arguments matching active sidecars.
   - `_build_relation_connection_resolver` checks per-response-key and shared prefetch window attributes on root instances, verifies N+1 safety (`_check_n1`), and wraps pre-fetched window rows in `_WindowedConnectionRows`.
